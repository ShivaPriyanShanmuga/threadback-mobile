# Working-demo plan — 2 minutes 30 seconds

Do not submit this script as evidence of a working recording. Record the actual application and label the illustrated example if it is shown. Final phone footage remains required for the proposed phone experience.

| Time | Actual screen / action | Narration |
|---|---|---|
| 0:00–0:15 | Show a real interrupted desk task. | “A checklist remembers that you started. It often forgets the detail you need when you return.” |
| 0:15–0:30 | Open Threadback on iPhone, create the task and steps. | “Threadback is a visual bookmark for unfinished physical work.” |
| 0:30–0:50 | Start the camera, set a workspace reference, place one marker. | “A reference connects the note to a place on the workspace. These are surface markers, not automatic object recognition.” |
| 0:50–1:15 | Speak a real checkpoint: “The base is finished. The divider is positioned, but not glued. Next: glue the left divider.” Review fields and attach a fresh camera photo. | “The important part is what’s unresolved. Completion stays under your control.” |
| 1:15–1:30 | Pause, leave the app, reopen it. | “Then an interruption happens. The task state and photo evidence are saved locally.” |
| 1:30–1:50 | Open the resume packet. | “Last completed. Left unfinished. Exact next move. No reconstructing the whole task from memory.” |
| 1:50–2:05 | Reacquire the reference, show companion/marker. Briefly obscure the surface to show markers hide when tracking fails. | “When alignment is uncertain, Threadback hides the marker. It asks you to reacquire the workspace.” |
| 2:05–2:20 | Mark the step complete, show progress advancing and unfinished detail clearing. | “Correct or undo any change. Finished work advances the thread without carrying an old warning forward.” |
| 2:20–2:30 | Show source and verification summary. | “Built for the phone you already have. Source and tests are public; real-device limitations are documented.” |

## Recording checks

- Use a familiar low-risk task with visible parts and a textured flat surface.
- Confirm camera and speech on the actual iPhone before recording.
- Include the app's true latency; label any cuts or time compression.
- Keep consent prompts and unrelated notifications out of the final take.
- Use original footage, music only if appropriately licensed, and accurate captions.
- Upload the final 2–3 minute working demonstration to YouTube or Vimeo; a local video file or script alone does not satisfy the submission requirement.
- Show current behavior only. Do not describe text rules as AI vision, or an illustration as live camera footage.
